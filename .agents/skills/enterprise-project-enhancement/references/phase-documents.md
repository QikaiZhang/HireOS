# Phase Documents

每个阶段文档使用相同结构：

```markdown
# 阶段名称
## 目标与业务价值
## 前置条件
## 修改范围
## 实施切片
## 交付产物
## 验证方案
## 风险与回滚
## 停止条件
## 面试证据
## 状态
```

## 推荐阶段

### Phase 0: Baseline

冻结现状快照，补齐运行说明、关键链路图、最小测试和基线指标。没有基线就不能声称“优化了多少”。

### Phase 1: Business Closed Loop

先补齐一个真实业务闭环：输入、规则、持久化、异步任务、人工审核、结果回写和审计。控制在一条可演示主路径及必要异常路径。

### Phase 2: Reliability

围绕超时、重试、幂等、限流、降级、死信、补偿和权限做增强。每个机制必须对应一个可复现故障或业务约束。

### Phase 3: Performance

建立压测模型和容量假设，再按证据优化缓存、索引、批处理、并发或队列。记录 P50/P95/P99、吞吐、错误率和资源成本，不只记录平均耗时。

### Phase 4: AI or Intelligence

只有当业务闭环已有稳定输入和反馈时引入 RAG、Agent 或模型能力。记录数据接入、切分、权限过滤、召回、重排、生成、工具调用、人工反馈和评估集。

### Phase 5: Production Simulation

用本地或测试环境模拟发布、扩缩容、故障恢复、备份恢复、监控告警和安全审计。明确哪些是生产等价验证，哪些只是演示模拟。

阶段之间不是必须全部实施。若某阶段的价值无法由当前项目规模验证，应降级为设计文档或实验记录，并说明原因。
