# Interview Package

## STAR-L 模板

```markdown
### 亮点：
- S（场景）: 用户、业务规模、原有痛点和约束
- T（任务）: 目标、SLO、交付边界
- A（行动）: 2~3 个关键动作；说明候选方案、取舍、实现和故障处理
- R（结果）: 基线、实测结果、业务影响；区分 verified / simulation
- L（复盘）: 失败、成本、未解决问题和下一步
```

## 追问分层

每个亮点准备三层问题：

1. 原理：组件或模式解决什么问题，边界是什么。
2. 工程：如何处理重试、幂等、超时、并发、数据一致性、权限和观测。
3. 取舍：为什么不用替代方案，成本是什么，规模扩大后哪里会先失效。

## 真实性约束

- 不声称没有做过的代码、压测、线上事故或团队职责。
- 不用孤立的“提升 3 倍”“召回率 94%”作为结论；必须给出数据集/流量模型、基线、环境、测量方法和限制。
- AI 项目必须能解释非 AI 的业务价值、人工兜底和错误处理。
- 个人贡献用“我负责的边界”表达，团队能力用“系统具备的能力”表达。
